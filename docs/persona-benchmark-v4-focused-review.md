# Persona v4 focused 실제 평가

2026-09-20, 기존 focused 12개 × 3명의 입력을 변경하지 않고 `JumZipPersona-v4`로 실행했다. Codex / fortune_audit(AI)가 36개 실제 본문 전체를 원래 도구 자료와 직접 대조했다. 항목별 다섯 축 점수와 원문 근거는 `tests/persona/benchmark-runs/v4/focused/ai-review.json`에 있다. **완전한 60개 수용 기준의 대체 검사가 아니며, 의미 품질은 여전히 실패다.**

처음 실행은 보수적인 사전 비용 예약 때문에 32개의 정상 응답 뒤에 중단됐다. 실제 사용량은 672.98 neurons였으나 다음 큰 프롬프트의 UTF-8 바이트 수를 모두 입력 토큰으로 보고 출력 900토큰까지 예약하면 남은 800 한도를 넘었다. 공급자 quota나 모델 오류가 아니었다. 원래 manifest의 `LOCAL_NEURON_BUDGET` 사건과 800 한도를 그대로 보존했다.

이후 합계 한도를 1,000 neurons로 늘리는 명시적 승인을 받아 미실행 4개만 같은 production/source hash와 같은 비용 예약 방식으로 별도 continuation에 기록했다. 원래 32개를 다시 실행하거나 유리한 답변을 선택하지 않았다. 최종 36개 모두 정상, HTTP36회, 실제 합계 **777.334575 neurons**다. 최초 실제 사용량과 continuation 비용104.35를 구분해서 기록하며 원본 중단을 없애지 않는다. 최종 실제 비용은 원래800보다도 작지만 사전 예약이 보수적이어서 중단됐던 것이다.

카드의 사용자/상대 위치를 바꾸거나 상호 호감을 분명하다고 확정하던 문제가 이번 표본에서는 줄었다. 은둔자 역방향과 경계 점수32·37·58도 보존됐다. 실제 비율을 함께 제공한 궁합에서는 대부분의 A/B 비율 비교가 정확해졌다. 다만 아홉 문장 보고서, 같은 문장의 반복, 존댓말 혼용, 비율에서 실제 성격을 확정하는 추론이 남는다.

확정 오류는 두 항목이다. `s02-unknown-hour:BOMI`는 정확한 오행 비율 뒤에 “이걸로 대운 방향은 추측할 수 있어”라고 했다. 오행 비율에서 대운 순역을 도출하는 규칙은 없으며, 제공되지 않은 계산 방법을 만들었다. `s07-no-invented-score:ARANG`은 궁합 점수·결혼 확률을 거부한 뒤 “B는 수35%가 가장 많다”고 했다. B의 목은48.3%이며 원래 자료와 추가한 최대 원소 필드 모두 목이라고 명시한다. 더 명시적인 사실을 전달해도 모델이 이를 잘못 읽은 사례다.

별도 backend의 v4 기억 회상 재현에서는 JSON Schema가 전달됐는데도 초기와 수리 모두 `toolReferences`를 빠뜨렸다. 두 응답은 finish_reason=stop, 출력56토큰으로 충분히 짧았다. 스키마 미전달이나 토큰 한도 문제가 아니라 모델의 형식 미준수다. 검증기가 제대로 차단했으며 빠진 필드를 임의로 채우거나 수용 기준을 낮추지 않았다. 또한 단순 취향 회상 질문을 사주 NATAL로 분류한 의도 추출 오류도 기록됐다. 근거: `docs/evidence/backend-recall-probe-v4.json`.

후속으로 같은 Cloudflare 무료 모델 범위의 작은 비교 시험을 검토한다. Qwen의 프롬프트를 계속 늘리거나 실패한 상태에서 전체84개를 반복하지 않는다. 모델을 바꾸더라도 원래 입력·원본 사실·구조 검증·수리1회·시간과 출력 한도는 동일하게 두며, 모델별 실제 과금 단위와 원문을 별도로 기록해야 한다. 아직 배포 모델 교체나 품질 통과를 의미하지 않는다.

기록: focused의 원래 `benchmark-progress.json`, `benchmark-results.json`, `benchmark-provider-attempts.jsonl`, `benchmark-baseline-manifest.json`; 별도 `continuation/results.json`, `provider-attempts.jsonl`, `manifest.json`; 그리고 합본 직접 검토 `ai-review.json`. 원문 SHA256 연결과 원래 코드 hash를 유지했다. 소스 hash는 실제 실행 당시 파일 바이트의 증거이며 Git 개행 정규화 후 다른 체크아웃의 바이트가 같은 의미임을 자동으로 증명하지 않는다.
