# JumZip 문구 정리 계획 — 검토 초안

작성일: 2026-09-20. 기준 소스: `7884a8b`. 이번 작업은 조사와 제안만 진행했으며 앱 문구·프롬프트·배포는 변경하지 않았다. 아래 대체 표현은 확정 원고가 아니다.

## 추천 방향

**불필요한 문장은 삭제하고, 필요한 안내는 실제 기능을 짧게 설명한다. 캐릭터의 개성은 인사와 대화에 남긴다.**

사용자가 지적한 홈의 두 문단은 다른 슬로건으로 채우지 않고 삭제하는 안을 추천한다. 이미 캐릭터 선택, 대화 시작, 타로·사주 진입 버튼이 있어 같은 내용을 다시 설명할 필요가 적다.

- 홈의 `오늘은 누구랑 이야기해볼까요?`는 선택할 행동이 분명하고 자연스러워 유지 후보.
- `정해진 미래보다, 지금의 당신을 위한 이야기.`는 삭제.
- `한 장의 카드, 타고난 흐름, 그리고 나를 기억하는 대화. 같은 고민도 누구와 나누느냐에 따라 다르게 보이니까.`는 삭제.
- 그 아래에는 `타로 보기`, `사주 보기`처럼 실행할 기능만 남긴다.
- 캐릭터별 짧은 소개나 대사를 남기더라도 같은 화면에 한 번만 쓴다. 채팅 중에는 고정 대사를 실제 반응처럼 반복하지 않는다.

`이야기`, `마음`, `흐름`을 금지어로 만들지는 않는다. 대화 내용이나 사주 개념을 설명할 때 필요한 표현은 유지하고, 정보 없이 분위기만 반복하는 사용을 줄인다.

## 조사 범위와 판정 방식

[원문 후보 목록](copy-review-inventory.json)에 45개 소스 파일의 문자열·템플릿 후보 1,323곳을 정리했다. 프런트엔드/HTML 후보 985곳, 서버/프롬프트 후보 338곳이다. **중복·내부 지시·미사용 필드를 포함한 탐색 건수이며, 화면 문구 수나 문제 건수가 아니다.** 실제 사용처를 함께 읽고 아래 수정 후보를 선정했다.

대상은 홈, 캐릭터 소개, 온보딩, 계정 연결, 채팅, 추천, 타로·사주·궁합, 출생정보, 기록·기억, 결과 상세·내보내기, 설정·삭제, 개인정보 안내, 오류·대기·빈 상태, 접근성 문구, 페이지 제목/설명이다. 도메인 정본 데이터·승인된 사주 규칙·과거 검증 원본은 표현 정리로 수정하지 않는다. 앞으로 생성될 모든 AI 답변을 조사한 것은 아니다.

판정은 세 가지로 한다.

1. **삭제:** 없어도 사용자가 다음 행동과 현재 상태를 이해할 수 있는 문장.
2. **수정:** 기능·상태·범위가 필요한데 비유, 중복, 모호한 표현 때문에 이해하기 어려운 문장.
3. **유지:** 자연스러운 인사, 명확한 기능명, 실제 추천 이유, 저장·삭제·동의·불확실성에 관한 필요한 설명.

## 실제 AI 대사의 말투는 별도 단계

현재 요청의 예시는 고정 화면 문구다. 먼저 위 UI를 정리하고, 실제 응답의 정형적인 말투는 별도 변경으로 검토한다.

읽기 조사에서 `persona/config.ts:29,49,68`, `prompt.ts:51,76`에 반응 → 감정 → 질문 같은 순서와 질문 한 개 지시가 반복되는 것을 확인했다. 매 답변이 비슷한 공감과 질문으로 끝나도록 유도할 가능성이 있다. **이번에는 새 모델 출력으로 그 인과를 검증하지 않았다.**

채택을 검토할 방향:

- 질문에 먼저 답하고, 답변에 꼭 필요한 정보가 부족할 때만 되묻기.
- 질문이나 점술 권유 없이 끝나는 답변도 허용하기.
- 사용자가 별일 없다고 말할 때 숨은 고민을 억지로 해석하지 않기.
- 보미의 빠르고 밝은 반응, 산이의 담백한 반말, 아랑의 차분한 존댓말은 유지하기.
- 인사·잡담·간단한 사실 질문·위로 요청·질문을 원하지 않는 상황·도구 결과 설명을 합성 예문으로 비교하기.
- 안전·점술 근거·기억 출처·구조화 응답 검증은 말투 변경과 함께 약화하지 않기.

사용하지 않는 필드를 먼저 고쳐 놓고 실제 화면이나 모델이 달라졌다고 판단하지 않는다. 현재 `characters.ts`의 description/loading/error, `config.ts`의 age/tagline/greeting, `PERSONA_UI_COPY.restored`는 실제 화면/모델 전달에 쓰이지 않는다. thinking은 화면읽기용이고 longWait는 20초 후 표시된다. 예문도 모두 주입되지 않으므로 선택된 예문과 실제 시스템 프롬프트를 기준으로 수정해야 한다.

운영 v4, 격리된 v4.1 수정본, 작업 중인 v12 후보가 나뉘어 있으므로 프롬프트 변경 시 배포 대상을 먼저 확정한다. 현재 코드 전체를 운영에 덮어쓰는 방식으로 문구를 반영하지 않는다. 모델 호출은 가용성과 제한을 확인한 후 필요한 소규모 비교만 수행한다.

## 적용 순서와 완료 조건

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 1. 방향 확인 | 홈·채팅·설정에서 대표 전후안을 검토하고 공통 UI의 담백한 톤 확정 | 삭제/유지 기준과 용어표가 합의됨. 이번 문서는 이 단계의 초안 |
| 2. 고정 UI 정리 | 홈·공통 영문 장식·채팅 중복 설명 삭제, 제목·버튼 명칭 통일 | 빈 영역·불필요한 선·번호까지 정리. 접근성 이름과 실제 버튼 행동 일치 |
| 3. 기능 안내 정리 | 오류·빈 상태·대기·계정·기억·출생정보·내보내기 상태 확인 및 문구 수정 | 확인되지 않은 저장/복구/기억 약속 없음. 재추첨/재해석, 대화/상담, 기억/출생정보가 구분됨 |
| 4. 결과 화면 정리 | 타로·사주·궁합·기록·이미지/텍스트 내보내기 표현 정리 | 정본·계산값·동의·불확실성 보존. 예전 기록에도 명칭이 자연스러움 |
| 5. 선택적 대화 말투 개선 | 승인된 페르소나 방향과 실제 주입 예문을 따로 수정·평가 | 반복 질문/과잉 공감 감소를 실제 출력으로 확인. 캐릭터별 말투와 검증 계약 유지 |
| 6. 통합 확인 | 데스크탑·모바일·확대 화면에서 전체 흐름 읽기 및 최종 배포 | 글자 잘림·빈 공간·중복 안내 없음. 최신 배포 파일과 검증본 일치 |

코드 단계마다 타입 검사, 관련 기존 테스트, 프로덕션 빌드를 수행한다. 표시 조건을 바꾸는 경우 해당 조건을 검증하고, 단순 문구 교체를 그대로 복제하는 테스트를 새로 늘리지는 않는다. 기존 텍스트 선택자와 접근성 테스트는 바뀐 실제 동작 이름에 맞춘다. 공개 전에는 전송→대기→성공/실패→재시도, 카드 저장→재해석/재추첨, 기록/내보내기, 계정·삭제 안내를 확인한다.

현재 공개 업로드와 AI 연결 검증의 미완료 상태는 이 문구 계획으로 해결됐다고 처리하지 않는다. 구현·배포는 방향이 정해진 뒤 별도 진행한다.
