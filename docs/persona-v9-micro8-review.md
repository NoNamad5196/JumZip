# Persona-v9 micro8 실제 결과 직접 검토

**FAIL 유지: 8개 중 7개 전달, 1개는 수리 후에도 계약 실패.** 전달된 7개에 대한 primary AI 직접 평가 평균은 **8.43/10(59/70), 확정 의미 Hard Fail 0**이다. 이는 부분 검사이며 원본 60+24개 합격을 의미하지 않는다. 실패한 한 건의 점수와 Hard Fail 필드는 `null`로 남겼다. 유효 응답 평균으로 운영 실패를 가리거나 전체 품질 통과로 확대하지 않는다.

검토자는 코드 작성에 참여한 **Codex AI / fortune_audit**다. 사람 검토 또는 독립 검토를 주장하지 않는다. 원본 입력 8개, provider 원문 10개, 전달 응답 7개를 모두 직접 읽고 고정된 다섯 축에 따라 점수를 작성했다. 이후 수행한 로컬 validator/request 재현은 근거 대조이며 의미 점수를 자동 생성하는 절차가 아니다. 이 검토 중 모델 호출·런타임 수정은 0이다.

별도 **Codex AI / contracts_audit** 독립 직접 검토는 `independent-ai-review.json`에 보존되어 있다. 전달7개 **65/70=9.29**, 확정 의미 Hard Fail0이며 같은 미전달1개는 무점수다. 이 검토자는 primary를 읽지 않고 평가했다. primary의59점과 독립65점은 상징/실제 심리 경계 및 설명 누락에 대한 축별 감점 차이로 각각 유지하며 합의 점수처럼 합치거나 어느 쪽을 덮어쓰지 않는다. 두 검토 모두 계약 실패1개를 의미 품질 합격으로 계산하지 않는다.

## 실행과 보존 근거

- 경로: `tests/persona/benchmark-runs/v9-micro8/`.
- 모델: `@cf/google/gemma-4-26b-a4b-it`, Persona-v9 / Intent-v4, 실제 provider의 `enable_thinking:false`, JSON object, output 900, 수리 최대 1회.
- 실제 8개 시도/8개 실행 완료, HTTP 10회, 유효 7개, 계약 실패 1개, 미전송 0개. `completed=true`는 실행 종료이며 품질 합격이 아니다.
- ledger 사용량 **444.468081 neurons**, 수리 2회의 합 **100.564642 neurons**. 모든 usage를 확인했다. 제안 cap800 안에서 종료했다.
- 전부 HTTP200/`finish_reason=stop`, 최대 completion **348 tokens**. 출력 상한·timeout·provider429 실패가 아니었다.
- 전달된 응답의 왕복 시간 중앙값 4.42초, 범위 2.06–12.40초. 수리 실패 사례는 9.94초였다. 이는 wall time이며 CPU 측정값이 아니다.
- 빈 직접 평가 template, 원본 results/attempts/manifest/selection은 수정하지 않았다. 새 `primary-ai-review.json`에 exact output/segments, input/output/raw/request SHA256, raw line, 다섯 축 점수 및 이유를 결합했다.
- 현재 입력 8개 hash가 frozen selection과 일치한다. 모델 통신을 금지한 로컬 provider replay에서 실제 직렬화 요청 hash **10/10**, 당시 소스 LF hash **32/32**, validator 결과를 모두 재현했다. 따라서 남은 수리 요청에도 v9의 구체 경로와 연속 복사 안내가 들어갔음을 확인했다.

A/B를 바꾸며 B시주를 미상으로 만든 모순, 알려진 날짜를 제공되지 않았다고 주장한 모순도 이번에는 없다. 다만 상대 내면의 추정, 후보값 설명 누락, 불필요한 출생정보 재요청은 별도 감점이며 해결 완료로 보지 않는다. 단일 작은 묶음에서 Hard Fail을 보지 못한 것을 전체 84개의 안전성·품질 보장으로 확장할 수 없다.

## 구조 실패와 수리 효과

실패 원인은 여전히 **선택 keyword를 본문에서 그대로 복사하지 않고 쉼표 목록으로 재조합하는 것**이다. 선택한 index·카드 방향·위치는 맞아도 연속 인용 계약을 충족하지 않는다.

`v5-reversed-owner-contrast:SANI`의 초기와 수리 모두 다음과 같았다.

| 카드 위치 | 실제 본문 | 제출한 textEvidence | 결과 |
|---|---|---|---|
| 0, 나의 은둔자 역방향 | 고립이나 회피 | 고립, 회피 | 연속 구절 아님 |
| 1, 상대의 연인 정방향 | 연결이나 끌림 | 연결, 끌림 | 연속 구절 아님 |
| 2, 관계의 절제 정방향 | 조율이나 균형 | 조율, 균형 | 연속 구절 아님 |

raw line8/9는 각각 completion318, `stop`이며 JSON content가 byte동일하다. `/interpretationEvidence/0/textEvidence` 등 구체 경로 및 `NOT_A_CONTIGUOUS_SUBSTRING_OF_TEXT` 진단이 담긴 실제 수리 요청을 hash로 재현했지만, 모델이 근거를 수정하지 않았다. schema 전달 누락, 토큰 부족, validator 변경이 원인이 아니다. 서버는 거짓 인용을 대신 생성하거나 완화하지 않았고 두 번째 실패에서 차단했다. 이 차단 결과는 유지해야 한다.

대조적으로 `10-retry-same-draw:ARANG`은 초기 raw line5의 두 span 오류를 수리 line6에서 해결했다. 본문과 카드 tuple은 그대로 두고 `고립시키거나 회피하며`, `조율과 균형이`라는 실제 연속 구절로 바뀌었다. 여러 keyword를 담은 연속 구절도 현재 계약 안에서 표현 가능하다는 관측이다. 이 한 번의 성공은 수리가 항상 작동한다는 증거가 아니며, 인용이 맞는 본문도 상징과 실제 심리의 경계를 흐릴 수 있다.

v8은 4유효/3무효/1미전송, v9은 7유효/1무효/0미전송이었다. 그러나 cap과 실제 출력 및 수리 발생이 달랐고 무작위 반복 실험을 하지 않았으므로 이 비율 차이를 v9 안내의 인과효과나 안정적인 완주율로 주장하지 않는다. 다음 변경안이나 추가 모델 실행은 이 문서에서 결정·수행하지 않았다.
